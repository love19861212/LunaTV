## 二、播放器修复

### 2.1 伪装分片修复 v4（`src/app/play/page.tsx`）

**背景**：#1 爱奇艺源分片为"图片伪装头 + 标准 MPEG-TS"。
源站先后用过 JPEG 伪装头（75 字节 / 263 字节）与 PNG 伪装头（89 50 4E 47 … IEND，共 181 字节），
分片 URL 后缀也变为 `.png`，导致固定头检测失效。

**v4 方案**（不再依赖图片类型或固定长度）：
- 首字节 `0x47` → 标准 TS，直接放行
- `ftyp/moov/moof/styp/sidx` → fMP4，直接放行
- 其他开头 → 在 64KB 内扫描 TS 同步（连续 10 个 188 字节包 + PAT 校验），定位后剥头
- 找不到同步 → 抛错，由调用方保留原数据

**验证**（实际编译出的 v4 JS + 3 个真实 PNG 分片）：
- 正确识别伪装，剥头后首字节 `0x47` 且全 188 对齐
- ffprobe 确认 H.264 1920×800 + AAC；ffmpeg 可无重编码转封装 MP4
- 标准 TS / fMP4 回归正确放行

**兼容性修复**：hls.js 实际传入的 fragment loader type 为 `media-fragment`
（非代码原先判断的 `fragment`），已兼容两种命名；关闭代理直连时 v4 才能真正生效。

### 2.2 代理环境下播放器类型识别修复

**根因**：开启 Cloudflare Worker 代理加速后，`applyVideoPlayProxy()` 把地址包装为
`{proxy}/m3u8?url=...`，外层 URL 不再以 `.m3u8` 结尾，ArtPlayer 自动类型识别失败，
`customType.m3u8`（含伪装分片修复 v4 与去广告 loader）整体被绕开。
现象：能解析出影片总时长（HLS 在跑）但无 `[伪装分片修复]` 日志、无法起播。

**修复**：创建 ArtPlayer 时显式指定 `type`——先用 `stripVideoPlayProxy()` 还原原始地址，
按后缀识别 `m3u8/mp4/webm/mov/mkv/flv`；无法识别时回退自动检测。

### 2.3 去广告过滤器 v4（管理面板「自定义去广告」，配置版本 5→6）

- 部署时间：2026-09-25 14:37 UTC；仅修改过滤器代码，未动任何视频源。
- #1《哪吒之魔童闹海》样本：1502 分片 → 1499，仅删除 3 个广告段，playlist 未破坏。

### 2.4 测速相关修复

1. **测速面板竖排**（`src/components/EpisodeSelector.tsx`）：窄栏下"视频源测速"文字与按钮被挤成竖排，
   加 `whitespace-nowrap` / `flex-shrink-0` 修复。
2. **自动测速不触发**：`enableOptimization` 开关注释写"默认开启"，但 localStorage 无值时代码返回 `false`，
   导致无痕/新设备下自动测速 `useEffect` 直接 return。已改为默认 `true`，与注释一致。

### 2.5 压进片子的硬广告

- 部分短剧源（如魔都动漫）的赌博广告文字是**直接压进视频像素**的（每帧都带），
  不是 m3u8 插片段。去广告过滤器只改播放列表，无法去除此类硬广告。
- 按"不禁用源"原则未做处理；用户侧可用「跳过设置」跳过片头（如广告仅在开头）。
